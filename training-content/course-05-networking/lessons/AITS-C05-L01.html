Learning objective

Explain the path from a device to an external service.

Explanation

A local area network connects nearby devices. A switch commonly connects wired devices within that network, a router forwards traffic between networks, and an access point gives wireless devices access to a network. One physical product may combine these functions. A Wi-Fi connection alone does not prove internet access.

Trace the path from the client through access, local switching, gateway and upstream connection to the service. A fault can affect one device, one wireless area, one VLAN or the whole site. Start by asking what works as well as what fails. Comparing affected and unaffected paths narrows the investigation without changing the network.

Synthetic example

A fictional laptop sees the office Wi-Fi name but cannot open websites. Another wired workstation works. Begin with the laptop/wireless path rather than declaring a site-wide ISP outage.

Practical exercise

Draw a laptop-to-internet path and mark which observations would distinguish a client fault from a shared fault.

Model response

Laptop → access point → switch → router → provider → service. Compare another client, wired access and another service using authorized tests.

Summary

Wi-Fi connection is not proof of internet Separate device and shared scope Compare working and failing paths
